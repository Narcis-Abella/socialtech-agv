# Point 7 kickoff: FAST-LIO2 submap → KISS-Matcher → small_gicp

Date: 2026-10-09. This is an implementation preflight, not an experiment or a compatibility claim.

- **Read in repository:** `01-investigacion-metodos.md` already surveyed and ranked the candidates, including the Humble Mid-360 FAST-LIO2/KISS/small_gicp wrapper by Ikunio. `02-protocolo-evaluacion.md` already defines the common 3D verification, alternative margin, multi-batch confirmation and truth firewall. No new survey or thresholds are introduced here. This checkout contains FAST-LIO2 build patches and the existing ROS nav bench, but no KISS-Matcher, small_gicp, or odometry-joined 3D submap builder. The reviewed upstream wrapper concatenates clouds directly; moving `/cloud_registered_body` cannot be substituted without transforming each scan to a common local frame.
- **Measured/read-only NX inspection:** the eco01 same-run `map_clean.ply` (4.2 MB) and `world.ply` (11 MB) exist. The former excludes the ceiling; the latter must be transformed from Voxel-SLAM world using the YAML `T_map_world` and cropped for outliers. In `socialtech:robot-nav`, Eigen 3.4, PCL 1.14 and oneTBB 2021.11 development packages exist; `numpy` exists, while Python `kiss_matcher`, `small_gicp` and `scipy` do not. This checks installed packages only, not source-build success. No NX build or registration run has occurred.
- **Read upstream:** [KISS-Matcher](https://github.com/MIT-SPARK/KISS-Matcher) provides C++/Python registration and ROS2 examples; its published Linux Python wheels are x86_64, so a Jetson source build remains to verify. [small_gicp](https://github.com/koide3/small_gicp) provides a local registration/refinement library; it cannot by itself search the global map. A source or aarch64 wheel path is available, but its behavior in the pinned Jazzy image remains unverified. The pinned upstream versions and license analysis are in `01-investigacion-metodos.md`.
- **Next concrete check:** prepare a separate research image or user-space build on the NX, pin both upstream revisions, and compile against the existing Jazzy/ARM toolchain without editing the `robot` stage. Reuse the existing FAST-LIO2 outputs, transform each deskewed scan by its timestamped odometry into one local frame, and keep the query submap independent of map/reference. Register against a correctly framed ceiling-inclusive map as well as declared map tiles, retain distinct hypotheses, refine each with small_gicp and apply the approved withheld-geometry and multi-batch gates before any AMCL handoff. Test transform direction and timestamp alignment before measuring success.
