# AMCL global preflight — EXPLORATORY / NOT FINAL BENCHMARK

Date: 2026-10-07. **V** = verified in code, installed image or run artifact; **I** = inferred/delegated engineering choice; **NV-P** = pending. This is point 6 only; it cannot establish reliability with at most three independent blocks per cell. The proposed AMCL run and acceptance observer must use no Voxel-SLAM reference, saved pose or reference-derived `/initialpose`.

## Data-use firewall, declared before the first AMCL run

Every window used here is irrevocably **DEVELOPMENT / EXPLORATORY** for this project. If any integration setting, AMCL parameter or gate is inspected or adjusted after seeing its result, that window and its spatial block cannot later serve as independent final-evaluation evidence. The original `tuning/final/heldout` split remains recorded in the point-5 private inventory and is not rewritten. Using a historical `final` or `heldout` row for debugging consumes its independence for future scored comparisons. Formal evaluation therefore requires new, prospectively reserved recordings with >=30 independent blocks per cell; the present smoke test reports individual outcomes only, **NO ESTADÍSTICAMENTE INTERPRETABLE** rate.

The evaluator alone would select real eligible rows and later score against Voxel-SLAM. The executor would receive only the chosen raw sensor-time range and fixed scenario budgets; AMCL would receive map, sensor-derived `/scan`, TF/odometry and its fixed parameters. Private CSV/JSON, reference files, split, true pose and truth-derived levelling must not be mounted into the candidate process. **NV-P:** process/filesystem isolation still needs a runner; none was launched in this preflight.

## Frozen observable acceptance and outcome

The point-4 AMCL gate requires >=90% normalized particle weight within 0.20 m and 5 degrees of a proposed pose, >=50 finite projected checking beams spanning >=90 degrees, >=70% endpoints within 0.15 m of occupied map geometry, and >=0.10 support lead over a searched distinct alternative. Covariance, pose publication and service completion are diagnostic, not acceptance. The 60 s deadline includes acquisition and computation. A committed pose outside 0.30 m XY or 8 degrees yaw at the same represented sensor timestamp is `wrong_accept`, absorbing for that attempt. Reference interpolation is exact or bracketed <=0.20 s, with no extrapolation or nearest-pose substitution. A non-accepting eligible positive is `false_reject_timeout`; integration/input failures are kept separately as `invalid_unscorable` or `operational_failure` per point 4.

## Preflight outcome: blocked before the first run

**V, protocol:** `02-protocolo-evaluacion.md` B3 requires a fixed, independently calibrated sensor height and mount extrinsic **before** cropping and scoring scan/map agreement. It explicitly labels the 0.53 m value in AGENTS.md as a hint, not calibration. `03-generador-posiciones.md` identifies the 0.532/0.534 m mapping values as reference-derived and therefore forbidden for query preparation. The existing `planar_odom` converts the sensor/body pose to `base_footprint` using `sensor_height`; that value controls the 0.10–1.80 m projection. An incorrect height changes the actual LaserScan and the acceptance support fraction.

**V, read-only board inspection:** neither target map YAML records a mount height or extrinsic; each records only `T_map_world` from map production. A filename search of the existing board map/work/repo directories found no independent mount-calibration artifact. This does not prove no calibration exists elsewhere. **NV-P:** documented origin, uncertainty and applicability of a fixed sensor height/extrinsic for each bag, and a sensor-only gravity/TF validation. The legacy `pose_eval.py check` obtains height from Voxel-SLAM reference and cannot fill this gap without leaking truth. The published mount value alone cannot be promoted to calibration while the point-4 rule remains frozen.

**Decision:** `AMCL_EXPLORATORY_BLOCKED` under the approved protocol. No ROS node, Docker container, bag replay or AMCL method was launched. No window was consumed by an observed result; the development/exploratory designation above remains the prospective policy for the first run. A strict S1 raw-frame frontend would require separate integration because FAST-LIO2's first-scan skip and warm-up cannot stand in for one CustomMsg without previous LiDAR history. S2 3 s remains the first intended trial once calibration and the truth firewall are implemented. Do not reinterpret the 60 s timeout as a workaround for missing geometry.

**Next integration requirement:** record an independent physical mount measurement or a separately documented sensor-only calibration, including sensor origin, floor definition, uncertainty, dataset applicability and source hash. Then test gravity levelling, TF and scan projection without Voxel-SLAM input; implement the observer and evaluator as separate processes and start with one S2 3 s window. Preserve the current historical split and collect new reserved data for any formal evaluation. No AMCL parameters or protocol thresholds were adjusted here.
